วันที่: 9 พ.ย. 2569 · ผู้เขียน: BA · ที่มา: ผู้บริหารสั่ง 9 พ.ย. 2569 "ผมต้องการ requirement ให้คนทำ ui ออกแบบเกี่ยวกับหน้าเบิกของ แล้วเขาต้องเข้าใจด้วยว่าต้องทำอะไรบ้าง เช่นเลือกของ เลือกชนิด และ
เลือกอื่นๆ เลือก job แล้วแจ้งเตือนให้ถูก เอาแค่หน้านั้นก่อน"
เอกสารนี้อธิบายหน้า "เบิกของ" ที่ใช้งานจริงใน mock ตอนนี้ (ฉบับ 8 พ.ย. 2569 หลัง IF49) เพื่อให้ designer ออกแบบหน้าจอใหม่ได้โดยรู้ว่าผู้ใช้ต้องทำอะไร เห็นอะไร และระบบต้องแจ้งอะไรเมื่อไร designer
เริ่มที่หัวข้อ 0 (สิ่งที่ต้องส่ง ข้อกำหนด สี ฟอนต์ ข้อมูลตัวอย่าง และภาพหน้าจอปัจจุบัน)
สรุป 5 บรรทัด
หน้านี้ให้ผู้ใช้ "เบิกของออกจากคลังไปใช้กับงาน" ให้จบในหน้าเดียว ใช้เวลาไม่กี่ครั้งแตะ ทั้งบนมือถือหน้างานและบนคอม
ลำดับตายตัว 3 ขั้น: 1 เลือกของ+จำนวน → 2 เลือกคลัง → 3 เลือกงาน แล้วกด "เบิกเลย" ขั้นถัดไปเปิดเมื่อขั้นก่อนครบ ขั้นที่ยังไม่ถึงโชว์เป็นแถบล็อกบอกว่าต้องทำอะไรก่อน
ของที่มีสเปกเยอะ (สายไฟ) ใช้ "ชิปกรอง" ชนิด/ขนาด/แกน/สี แทนการอ่านชื่อยาว ๆ
ตัวเลขทุกตัวต้องมีคำกำกับ (ขอเบิก / มีในคลังนี้ / ขาด) และตัวเลขแต่ละชนิดโผล่ที่เดียว (กฎ IF48)
มีข้อความแจ้งเตือนในหน้านี้และที่ส่งถึงคนอื่นรวม 75 รายการ (หัวข้อ 5) ทุกข้อมีข้อความปัจจุบัน และบางข้อมีข้อเสนอแก้ถ้าข้อความเดิมไม่ชัดหรือขาด

ลำดับบนจอ: รายการที่เลือกแล้ว (ถ้ามี) อยู่บน → ปุ่ม/ตัวหาของอยู่ล่าง (IF48) ตัวหาของพับเหลือปุ่ม "เพิ่มของ" เมื่อมีรายการแล้ว กดเพื่อเปิด มีปุ่ม "ปิด" พับกลับ
ตัวหาของ (ตามลำดับบนจอ):

ไม่แสดงตัวเลขสต็อกที่ขั้นนี้เด็ดขาด (มี/ขาด อยู่ที่ขั้น 2 เท่านั้น IF48)

2. ลำดับคลัง: คลังที่ไม่ล็อกก่อน → คลังที่ครบก่อน → ครบเมื่อรวมยอดรอยืนยัน → สัดส่วนที่ครอบคลุมมากกว่า → ชื่อ
3. "แนะนำ" = คลังแรกที่มีของครบตอนนี้ ถ้าไม่มีคลังไหนครบ ใช้คลังแรกที่จะครบเมื่อยอดตั้งต้นที่รอยืนยันถูกยืนยัน
4. เลือกอัตโนมัติ: ทำเฉพาะตอนยังไม่มีคลังที่เลือก และ (ก) มีคลังเดียวที่ใช้ได้ หรือ (ข) มีคลังเดียวที่ครบ หรือ (ค) ไม่มีคลังครบแต่มีคลังเดียวที่ครบเมื่อรวมยอดรอยืนยัน · ผู้ใช้เปลี่ยนได้เสมอ · ไม่ทับคลังที่ผู้
ใช้เลือกเอง · การเลือกอัตโนมัติไม่ย้ายเคอร์เซอร์ (ผู้ใช้อาจกำลังพิมพ์จำนวน) ส่วนเลือกเองแล้วเคอร์เซอร์ไปช่องงาน
5. มีคลังเดียว: ไม่มี dropdown แสดง "เบิกจาก {ชื่อคลัง}" + ตาราง
6. ยังไม่เลือก: ข้อความ "เลือกคลังเพื่อดูว่ามีของพอไหม" (N26) ถ้าไม่มีของในคลังไหนเลย: ข้อความ N25 เหนือ dropdown
7. ตารางรายละเอียดของคลังที่เลือก (เฉพาะคลังที่เลือกอยู่ ไม่มีกรอบซ้อน): คอลัมน์ ของ | ขอเบิก | มีในคลังนี้ | ผล
ผล: "พอ ✓" · "ขาด N {หน่วย}" · "ไม่มี" (N32–N34)
"มีในคลังนี้" แสดงจำนวนที่ ใช้เบิกได้จริง (หักที่ถูกกันให้ใบเบิกอื่นแล้ว) สายม้วนแสดง "(N ม้วน)" ต่อท้าย
ถ้ามียอดตั้งต้นรอยืนยัน: แถวย่อยสีฟ้า N35
บนมือถือตารางเรียงเป็นแถวซ้อน (ชื่อบน ตัวเลขใต้ มีป้ายคำ "ขอเบิก" "มี" กำกับทุกตัวเลข) ห้ามตัดป้ายออก
ใต้ตาราง (หลังเลือกคลัง) เป็นพื้นที่ "ปัญหา" รวมที่เดียว:
กล่องแดง: รายการที่เบิกไม่ได้ (N37–N39) ระบุชื่อสินค้า
กล่องเหลือง: ของขาด → ระบบจะสร้างรายการต้องซื้อให้ (N40–N42) ไม่แสดงถ้าใบเบิกนี้ต้องรอหัวหน้าอนุมัติ (เพราะยังไม่มีการสร้างอะไร)
ปุ่ม "สลับไปคลังที่มีของพอ" ต่อ 1 คลัง (N43) แตะแล้วเปลี่ยนคลังที่เลือกเลย
สายม้วน: บล็อก "ม้วนที่จะตัด: {ชื่อ}" พับไว้ (เปิดเองเมื่อรายการนั้น error) ข้างในมี: ตัดจากม้วนไหน (รหัสม้วน ที่ชั้นไหน) · ตัวเลขม้วน "ม้วนมี · ตัด · เหลือ" (ป้ายคำกำกับทุกตัว) · คำเตือนเศษม้วน (N45) ·

ขั้นที่ 3 · เลือกงาน (บังคับ)
เปิดเมื่อเลือกคลังแล้ว ผู้ใช้ต้องทำ: บอกว่าเบิกไปใช้กับงานไหน (เพื่อให้ต้นทุนเข้างานถูก)
ช่อง "ค้นหางาน" (autocomplete + ปุ่มลูกศรเปิดรายการ) เปิดรายการเมื่อโฟกัส แสดงงานที่เปิดอยู่ 8 งาน (งานที่ผู้ใช้ใช้ล่าสุดขึ้นก่อน) พิมพ์แล้วค้นจาก รหัสงาน ชื่องาน ลูกค้า ไซต์ (ไม่เกิน 20) แต่ละแถว:
ชื่องาน + รหัสงาน · ลูกค้า
แถวแรกของรายการ "+ เพิ่มงานใหม่ "{คำที่พิมพ์}"" และปุ่มข้างช่อง "+ งานใหม่"
งานล่าสุด: ชิป 3 งานล่าสุดของผู้ใช้ (ชื่อ + รหัส) 2 คอลัมน์บนมือถือ แตะ = เลือก (เป็นทางลัด ไม่เลือกให้เอง) แตะซ้ำที่งานที่เลือกอยู่ = ยกเลิก ไม่แสดงถ้าผู้ใช้ยังไม่เคยเบิก
ปุ่ม ✕ ล้างงาน ปรากฏเมื่อมีค่าในช่อง
เลือกได้เฉพาะงานที่ "เปิดอยู่" งานที่ปิดแล้วไม่โผล่ ถ้าพิมพ์แล้วไม่ได้แตะเลือก ปุ่มเบิกใช้ไม่ได้ + ข้อความ N48
กล่อง "เพิ่มงานใหม่" (เต็มจอบนมือถือ): ฟิลด์ ชื่องาน (บังคับ "เช่น ติดตั้งแอร์ ห้องประชุม") · ลูกค้าหรือสถานที่ (ไม่บังคับ) · ถ้าชื่อคล้ายงานที่เปิดอยู่ แจ้งเตือน N51 พร้อมปุ่ม "ใช้งานนี้" (ไม่บล็อก) · ปุ่ม
"ยกเลิก" "บันทึก" (จางจนมีชื่อ) · บันทึกแล้ว สร้างงานทันที เลือกงานนั้นให้และไปปุ่มเบิก toast N52 · ไม่สร้างงานตอนกดเบิก (เปลี่ยนจากเดิมแล้ว)
ส่วนท้าย · หมายเหตุ + ปุ่มเบิก
เปิดเมื่อเลือกงานแล้ว
หมายเหตุ (ไม่บังคับ): ปุ่มพับ "หมายเหตุ (ไม่บังคับ)" ถ้ามีข้อความแล้วต่อท้าย "(ตั้งไว้ 1)" เปิดแล้วเป็นช่องข้อความ "เช่น เอาไปไซต์เช้านี้"
แถบล่าง: บนมือถือ ติดล่างจอ (ปุ่มเห็นตลอด) บนคอมเป็นแถวธรรมดาชิดขวา เรียงจากบนลง: กล่อง error จากระบบ (N56) → บรรทัดแดง "เบิกไม่ได้: …" (N55) → ข้อความ "ต้องให้หัวหน้าอนุมัติ…" (N54
ถ้ามี) → ปุ่ม
ปุ่ม: "เบิกเลย" (ไอคอนติ๊ก) หรือ "ส่งเบิก" (ไอคอนส่ง) ถ้าผู้เบิกไม่ใช่หัวหน้าและหัวหน้าเปิดสวิตช์อนุมัติ · สูง ≥48px เต็มความกว้างบนมือถือ · ใช้ไม่ได้ (จาง) เมื่อมีรายการเบิกไม่ได้ หรือกำลังส่ง
กดแล้ว: ปุ่มหมุน ระบบทำงานจบทันทีในครั้งเดียว (ไม่มีหน้าโหลดยาว) ผลลัพธ์แทนที่ฟอร์ม (หัวข้อ 6)

9. Acceptance criteria (Given / When / Then)
ขั้น 1 · เลือกของ
IP-AC1 Given เปิดหน้า "เบิกของ" ใหม่ · When ยังไม่เลือกอะไร · Then เห็นหัวขั้น 1 ช่องค้นหา (ข้อความช่วยตามข้อ 3) ใช้บ่อย (ถ้ามีประวัติ) หมวด และแถบล็อก 3 แถบ (N08–N10) ไม่เห็นขั้น 2–3
IP-AC2 Given ผู้ใช้พิมพ์ชื่อ ยี่ห้อ รุ่น หรือรหัสผู้ขายบางส่วน · When ผลลัพธ์ขึ้น · Then การ์ดมีชื่อ ยี่ห้อ·รุ่น และ "มีทั้งหมด …" หรือ "ไม่มีของ" เรียงตามกติกาข้อ 3 สูงสุด 8 ใบ และมี "แสดงเพิ่ม (อีก N)"
ถ้าเกิน
IP-AC3 Given ค้นหาไม่ตรงสินค้าใด · When ผลลัพธ์ว่าง · Then เห็น "ไม่พบสินค้า" และแถว "สร้างสินค้าใหม่ "{คำค้น}"" (ไม่เห็นแถวสร้างถ้าชื่อซ้ำทุกตัวอักษร)
IP-AC4 Given ผลลัพธ์มีสายไฟและผู้ใช้เลือกหมวด "สายไฟ" · When ดูตัวกรอง · Then เห็นแถวชิป ชนิด/ขนาด (sq.mm)/แกน/สี เฉพาะแถวที่มีค่ามากกว่า 1 ค่า แต่ละชิปมีตัวเลขจำนวนสินค้า
IP-AC5 Given เลือกชิป "THW" · When ดูแถวขนาดและสี · Then เหลือเฉพาะค่าที่ THW มี ผลลัพธ์เหลือเฉพาะ THW ชิป THW เป็นสีหลักอ่านชัด แตะซ้ำแล้วกลับเป็นไม่เลือก
IP-AC6 Given เลือกชิปหลายแถว (เช่น THW + 2.5 + ดำ) · When ดูผลลัพธ์ · Then มีเฉพาะสินค้าที่ตรงทุกชิป และมีลิงก์ "ล้างตัวกรอง" ที่ล้างหมวดและชิปทั้งหมดแต่ไม่ล้างคำค้น
IP-AC7 Given ผู้ใช้ยังไม่เลือกหมวด ไม่พิมพ์อะไร ไม่เลือกชิป · When เปิดหน้า · Then ไม่เห็นแถวชิปสเปก (หน้าแรกสั้น)
IP-AC8 Given แตะการ์ดสินค้า · When เพิ่มสำเร็จ · Then เกิดแถวในรายการ "รายการที่จะเบิก (1 รายการ)" เคอร์เซอร์อยู่ที่ช่องจำนวนของแถวนั้น ตัวหาของพับเหลือปุ่ม "เพิ่มของ" การ์ดนั้นแสดง "เพิ่ม
แล้ว"
IP-AC9 Given สินค้านั้นเพิ่มไปแล้ว · When แตะการ์ดซ้ำ · Then ไม่เกิดแถวใหม่ จอเลื่อนไปแถวเดิม เห็นกล่องเหลือง N05 ประมาณ 6 วินาที (หายเมื่อแก้จำนวน)
IP-AC10 Given มีรายการ 3 ชิ้น · When ดูแถว · Then แต่ละแถวมีป้าย "ขอเบิก" ช่องจำนวนพร้อมหน่วย ปุ่ม ✕ ≥ 44px และ ไม่มี ตัวเลขมี/ขาดในขั้นนี้
IP-AC11 Given จำนวนช่องใดว่างหรือเป็น 0 · When ดูหน้า · Then ขั้น 2 ยังเป็นแถบล็อก N08 (และข้อเสนอ N06 ถ้า designer ใช้)
IP-AC12 Given ผู้ใช้กด ✕ ที่รายการหนึ่ง · When ลบ · Then แถวหายทันที ถ้าเหลือ 0 รายการ ขั้น 2–3 หายและตัวหาของเปิด
